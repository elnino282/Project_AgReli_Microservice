# AUD-S0-002 — Compose internal API trust boundary

## Invariant

Các endpoint `/api/v1/internal/**` chưa có service credential chỉ được reachable trong private Compose network; untrusted host client không được bypass gateway bằng port service.

## Reproduction trước fix

Compose publish toàn bộ cổng 8081–8092 ra mọi interface host, trong khi nhiều resource server `permitAll` internal path. Gateway không route `/api/v1/internal/**`, nhưng direct-port request bỏ qua boundary này.

## Root cause và fix

Development convenience ports biến network trust assumption thành public host surface. Bỏ host `ports` của 12 business services và dùng `expose`; chỉ gateway 8080 là application ingress. Container-to-container, healthcheck và Prometheus vẫn dùng Compose network.

Đây là network boundary cho Compose, chưa thay thế service identity/mTLS ở môi trường multi-host/Kubernetes. Rollback bằng `git revert`.

## Acceptance — đạt cho Compose 2026-08-14

- `scripts/verify-compose-boundary.ps1` xanh: Compose config không có published port cho service 8081–8092.
- Runtime TCP matrix từ host xác nhận `127.0.0.1:8081..8092` đều không accept connection.
- Gateway 8080 vẫn là application ingress; grep gateway route không có mapping `/api/v1/internal/**`.
- Full dev stack trước Giai đoạn 3 đã có 12 service healthy/gateway 200, chứng minh health/internal calls vẫn chạy trong Compose network.

Finding được đóng `FIXED` trong phạm vi single-host Compose. Multi-host/Kubernetes vẫn cần service identity/mTLS và là deployment hardening riêng, không được suy diễn từ network isolation này.
