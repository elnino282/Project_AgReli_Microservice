# AUD-S0-001 — Deterministic Compose readiness

**Trạng thái: FIXED 2026-08-14.**

## Invariant

Một service chỉ được khởi động sau khi MySQL đã chạy xong bootstrap schema/quyền và mọi dependency bắt buộc đã trả health `UP`.

## Reproduction trước fix

1. `docker compose config` cho thấy MySQL dùng `mysqladmin ping` không xác thực.
2. Probe này có thể thành công khi daemon đã nhận kết nối nhưng `init-mysql.sql` chưa tạo đủ 11 schema và chưa cấp quyền cho `springuser`.
3. `season-service`, `finance-service`, `incident-service`, `sustainability-service`, `marketplace-service`, `admin-reporting-service`, `delivery-service` và dependency của AI còn dùng short syntax hoặc `service_started`, nên Compose không chờ health của downstream.

Runtime 2026-08-14 đã xác nhận MySQL authenticated schema probe, full Compose build/up/wait và gateway health xanh sau khi Chroma probe được sửa.

Giai đoạn 3 thử cold-start lại project `vietfuture_audit` từ volume mới. MySQL/RabbitMQ/Chroma healthy trước lớp service đầu; log xác nhận Flyway tạo schema history và áp migration trên schema trống. Khi dependency chain tiếp tục khởi động, Docker Desktop API trả HTTP 500 và ngừng phản hồi do chạy đồng thời hai stack JVM; gateway audit chưa được tạo và không có full-stack evidence. Đây là blocker môi trường, không phải bằng chứng season/application fail. Finding vẫn `IN_FIX`; không được đóng từ lần chạy một phần này.

## Root cause

- Healthcheck đo process liveness thay vì application readiness.
- Dependency graph trộn `service_started` và `service_healthy` dù các service đã khai báo healthcheck.

## Thiết kế fix

- MySQL probe đăng nhập bằng application credential và `USE` toàn bộ schema được bootstrap. Lệnh chỉ exit 0 khi schema và grant đều sẵn sàng.
- Mọi dependency có healthcheck được chuyển sang long syntax với `condition: service_healthy`.
- Không đổi port, schema, dữ liệu hay application behavior.

## Compatibility và rollback

- Compatible với volume mới và volume hiện tại nếu `init-mysql.sql` trước đây đã chạy thành công.
- Rollback: `git revert` patch này. Không có migration và không xóa volume.

## Acceptance

- `docker compose -f docker-compose.yml config --quiet` xanh.
- `docker compose -f docker-compose.yml -f docker-compose.audit.yml config --quiet` xanh.
- Khi Docker daemon ổn định: bảo đảm project audit cũ đã được dọn, cold-start audit stack ít nhất hai lần từ audit volume mới; không service nào kết nối DB/dependency trước readiness.
- Không chạy dev stack và audit stack đầy đủ đồng thời trên Docker Desktop nếu tài nguyên không đủ; ghi rõ project/volume và không đụng volume dev.

### Evidence 2026-08-14

- Docker Desktop được restart theo ủy quyền sau khi Engine API treo; dev project chỉ được `stop`, không remove container hoặc volume.
- Trước mỗi lần chạy, `scripts/audit-stack.ps1 -Action down` xóa đúng project `vietfuture_audit`; kiểm tra sau teardown xác nhận không còn container/volume mang label project audit.
- `docker compose ... config --quiet` xanh cho cả base và base + audit overlay.
- Cold-start lần 1 từ năm volume audit mới: `up --wait` exit 0 sau khoảng 193,5 giây.
- Cold-start lần 2 sau teardown đầy đủ và tạo lại năm volume: `up --wait` exit 0 sau khoảng 194,1 giây.
- Mỗi lần có đủ 22 container audit; 12 business service đều healthy. MySQL healthcheck authenticated kiểm tra đủ 11 schema, trạng thái `healthy`, failing streak 0.
- Gateway audit tại `127.0.0.1:18080/actuator/health` trả HTTP 200 và status `UP`.
- Log toàn stack không match `Communications link failure`, `Connection refused`, `Unknown database`, `Access denied` hoặc `APPLICATION FAILED TO START`.
- Output Compose thể hiện lớp identity/catalog/farm/inventory chỉ start sau MySQL/RabbitMQ healthy; các lớp season, finance/incident, sustainability và gateway tiếp tục theo đúng dependency chain.
